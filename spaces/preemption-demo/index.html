Priority scheduling for local LLMs

GitHub PyPI

Instant chat replies for local LLMs — even while heavy background tasks are running on your CPU.

The Problem: Local AI runtimes (like Ollama and llama.cpp) process one request at a time. If a background job is running—like document summarization or batch processing—your chat messages are stuck waiting in line until the entire background job finishes.

The Solution: Lattice adds priority scheduling. When you send a chat message, Lattice immediately pauses the background task, answers your message with zero delay, and then resumes the background task right where it left off.

How Lattice Works

Benchmark results measured on an x86-64 CPU using Qwen2.5-0.5B with llama.cpp backend.

1. Immediate Preemption

When an interactive chat message arrives, Lattice pauses the running background generation in under 1 millisecond.

2. Zero Lost Progress

The background task's memory state is held safely in RAM. When the chat finishes, the task resumes from the exact token without repeating past work.

3. Memory Guard

Lattice continuously monitors available host memory before admitting tasks to protect against out-of-memory errors on laptops and desktops.

Wait Time vs Background Task Length

Without Lattice, wait time increases with task length. With Lattice, wait time stays constant at ~12 milliseconds.

Getting Started

Lattice exposes standard OpenAI-compatible endpoints on port 8000.

1. Install 
pip install lattice-inference

Available on PyPI.

2. Initialize 
lattice init

Automatically provisions llama.cpp and configures RAM.

3. Serve 
lattice serve --model model.gguf --preset chat

Starts the priority-enabled server.
