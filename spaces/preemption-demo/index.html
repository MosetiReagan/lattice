Instant Interactive Responses Under Heavy CPU Contention

Standard local LLM engines (Ollama, llama.cpp, vLLM CPU) execute incoming requests sequentially in a strict First-In, First-Out (FIFO) queue. When a long background batch task runs, concurrent interactive user queries suffer tens of seconds of queue delay.

Lattice introduces token-boundary preemption with state retention: high-priority requests preempt running background tasks in sub-millisecond time, receive immediate Time-To-First-Token (TTFT), and the background task resumes without lost compute.

System Architecture & Empirical Findings

Tested on x86-64 CPU hardware running Qwen2.5-0.5B-Instruct-F16 with llama.cpp backend.

1. Token-Boundary Preemption

Inference yields at discrete token boundaries. Active attention states remain coherent without corrupting in-flight context or forcing request aborts.

2. Zero-Copy KV State Swap

Preempted KV cache pointers are transferred to host RAM in sub-millisecond time. Upon resumption, generation continues from the exact checkpoint without recomputation.

3. Memory Guard Protection

Dynamic host reserve monitoring verifies available system RAM before admitting preemptive turns, preventing memory exhaustion under concurrent workloads.

Empirical Scaling: Queue Delay vs Background Workload Length

Sequential FIFO queue delay scales linearly with background token count, whereas Lattice queue delay remains constant at ~12ms.

Quickstart & OpenAI-Compatible Integration

Compatible with OpenAI SDKs, LangChain, LlamaIndex, Cursor, Continue, and Open WebUI.

1. Installation 
pip install lattice-inference

Install via PyPI with full CLI and server runtime.

2. System Provisioning 
lattice init

Detects CPU instruction sets, provisions llama.cpp binary, and configures RAM headroom.

3. Start Server 
lattice serve --model model.gguf --preset chat

Runs OpenAI-compatible server at port 8000 with preemption enabled.
