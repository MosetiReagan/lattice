# Logical KV prefix optimization

Implemented after independent speculative tests: `src/lattice/cache/prefix.py` manages the eligibility/lifecycle of one native llama.cpp slot. It compares exact prefix token tuples plus tenant, complete model/tokenizer artifact identity, backend build, context limit, KV type and positional configuration. TTL, logical byte limits, invalidation, eviction and observed reuse statistics are explicit. Default minimum prefix is 64 tokens. Unknown model KV accounting disables this path. Cross-tenant reuse is forbidden.

This manager does **not** implement a physical paged KV allocator, quantized-cache kernel or response-text cache. The model backend owns fixed-capacity KV storage and native prefix reuse. Logical limits bound which dense KV prefixes may be reused, not physical RSS. Native cache fragmentation, byte allocation overhead and memory savings are not measured. An oversized remembered prompt is invalidated instead of promising partial physical eviction.

Standard generation sets cache_prompt=false and invalidates the logical lease. Cached generation can request reuse only when the policy approves exact compatible tokens; a cold/short request still computes the full prompt. Cancellation, strategy transitions requiring worker restart and worker termination invalidate the lease. The current authenticated API has one operator security domain; multi-tenant auth is not implemented.

The paired experiment warms the same exact prompt once for **both** arms before each measured request, randomizes arm order and checks full greedy token equality. Its scope is warmed repeated-prefix performance, not an amortized end-to-end speedup including the priming requests. It also includes short prompts where the minimum-prefix rule declines reuse. Full run commands: `uv run --no-sync python experiments/cache_cpu.py --output benchmarks/results/new-cache-session --trials 30`. Three independent sessions are needed for repeatability evidence.

Important telemetry distinction: native terminal `tokens_cached` describes slot contents and is not an actual hit count. Actual prefix reuse is the native timing field `cache_n`. An early pilot exposed this distinction; its raw `tokens_cached` wrapper field is unsuitable for hit-rate reporting. Corrected experiments use `backend_timings.cache_n`, preserve the raw pilot, and must report misses and actual reused tokens independently. Identical outputs from a finite test set do not prove numerical equivalence for all batch shapes or prompts.
