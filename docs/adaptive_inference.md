# Adaptive execution — deterministic rules-1

The pure controller consumes request features, compatible path profiles, quality status and a resource snapshot. It chooses the measured lowest-latency eligible path while preserving explicit model identity and output/sampling constraints. No learned policy or semantic task-complexity inference is implemented. Explicit standard requests remain standard. Unknown/experimental profiles cannot silently become defaults.

Eligibility requires matching model/backend hashes, recorded CPU capability fingerprint and thread count, compatible input/output bounds, at least 30 trials and three sessions, no observed greedy mismatch and an approved quality scope. Native stochastic optimizations are not qualified. CPU/GPU presence and memory availability are separate from claimed accelerator support. The current policy knows only CPU paths. Policy metadata includes version, reason, evidence ID, evidence-file SHA-256 and evidence coverage; coverage is not a probability that an answer is correct.

`build_policy_evidence.py` qualifies only exact prompt hashes already compared in all three cache experiments. Generalizing a profile from synthetic prompts to unrelated real-world questions would overstate the available quality evidence, so arbitrary prompts fall back to standard. Cache prefix tokens must also match the isolated live lease. A cold adaptive request computes normally and may seed a future compatible lease. An exact known warm prefix can select cached execution. Negative speculative measurements and unqualified Q4/Q8 task quality keep those out of automatic selection.

A registry can name an operator-controlled policy JSON file. Until it exists/loads successfully, adaptive selection has no qualified profiles and executes standard with an explanation. Live feedback is recorded, not used to mutate policy silently. Replacing a policy requires an explicit versioned file/reload. The controller is backend-independent; the adapter exposes live features and executes the selected native path. Kernel, KV storage and draft verification remain delegated.

Memory preferences set a worker RLIMIT_AS address-space ceiling and may force worker reload; they are not a GPU quota. Impossible weights-plus-working estimates fail before load. An estimated-compute budget requires a measured profile or fails explicitly. A latency budget is a target, not guaranteed elapsed time; the request deadline remains the enforced time bound. No controller is permitted to truncate context or lower max_tokens to hide an infeasible request.
