# Baseline security and reliability

Implemented: strict public request schemas, input/body/context/output bounds, operator-only registry paths, model/backend/shared-library SHA-256 checks before worker load, private loopback worker with random bearer key, CPU-only execution, worker address-space ceiling, no core dumps, optional API authentication, mandatory authentication for non-loopback CLI binding, a global bounded per-minute rate limit, bounded queue and request deadlines. Prompt contents are never executed by Lattice. No filesystem/download/slot-save endpoint is exposed by its API. Backend HTTP endpoints remain private implementation details, not public proxy routes.

Request cancellation and errors are isolated by terminating the single active worker when needed. The next request reloads verified artifacts. API health describes the gateway, not model quality; successful inference is the real readiness evidence. Native logs are operator-only files created with mode 0600 and may contain backend diagnostic information. JSONL records omit prompt/output text and credentials; API metrics expose recent timing/configuration records to authenticated clients when authentication is enabled.

Limits: address-space RLIMIT_AS is not a GPU/RSS quota or a container sandbox. Host availability checks are estimates, not guaranteed memory reservations against other processes. Model metadata is parsed by native code; hashes prevent unapproved changes, not upstream vulnerabilities. Registry and executable artifacts are trusted operator inputs. Backend startup uses a port-selection race mitigated by a random credential and process-exit checks. Local privileged users can inspect worker credentials/process memory. Authentication has no built-in TLS; use a TLS reverse proxy for remote traffic. Rate limiting is global, not per-tenant. Scheduling, durable recovery, crash supervision, slow-client hardening and multi-tenant cache sharing are not release-certified. The Linux worker now sets a parent-death SIGTERM and verifies its parent PID before exec; a process-lifecycle test checks parent-crash cleanup. A supervisor/container is still recommended for service recovery. Benchmark execution is a bounded authenticated live-serving profiling job; it does not expose arbitrary prompts, paths, commands or unbounded research runs.

This development build is not a hardened public inference service. Security features and limitations are reported separately from the Lattice 1.0 acceptance gates.
