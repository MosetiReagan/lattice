# Profiling and measured experiment records

Each admitted request writes JSONL metadata with actual model/backend hashes, precision, CPU device, strategy, policy/evidence ID, fallback, queue depth/wait, timestamp, prompt/completion counts, configured context, sampling, client TTFT, total time and native prefill/decode timings where exposed. Runtime metrics retain counters and the last 100 records. Prompt/output text and credentials are omitted from normal audit logs. Public synthetic experiments intentionally retain their declared inputs/outputs separately for reproducibility.

`worker_startup_ms` includes artifact hashing/process/readiness, not pure model loading. Preloaded-server TTFT excludes startup; a one-shot CLI can include it. Native `prompt_ms` and `predicted_ms` use upstream semantics. Chunk intervals are not token intervals when UTF-8 buffering combines tokens. Actual cached prefix tokens come from native `timings.cache_n`; terminal `tokens_cached` must not be mistaken for hits. Unavailable draft-only/verification-only times and target forward counts remain unavailable.

The benchmark runner exports canonical raw JSONL, CSV, manifests and descriptive summaries. It samples Linux worker RSS every 10 ms, with sample count and explicit naming; this is a sampled per-window high, not exact allocator peak or incremental per-request memory. Concurrent requests sample the same worker, so their RSS values cannot be added. New sampler code also records worker VmSwap; original frozen runs did not, which limits their isolation audit. Host swap use by unrelated processes is not a worker measurement. No GPU utilization, energy or bits-per-byte values are invented.

P99 requires at least 1,000 observations; 30-trial runs report it unavailable. Paired cache analysis retains all 90 equal-token pairs across three sessions and computes seeded bootstrap intervals, while disclosing shared-VM/development activity and exclusion of symmetric priming. No confidence interval converts these synthetic workload observations into a production guarantee.

`lattice benchmark` runs bounded configured workloads; `lattice profile` defaults to three observations as a pilot. `lattice compare` measures both explicit models and labels different-artifact comparisons. `lattice optimize` reports available qualified policy evidence without modifying configuration. API benchmark jobs are authenticated live-serving profiles (at most five short requests), distinct from isolated research benchmarks.

`python scripts/build_dashboard.py` exports only completed measured summaries to `dashboard/data.json`. Serve locally with `python3 -m http.server 8080 --bind 127.0.0.1 --directory dashboard`. Missing observations display “Unavailable”, not fabricated example metrics. The dashboard is a local report viewer, not a public administrative service.
