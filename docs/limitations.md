# Development-build limitations and release concerns

This is not Lattice 1.0. Real CPU generation, streaming, bounded priority admission, explicit model/precision switching, greedy native speculation, isolated prefix eligibility, benchmark/quality infrastructure and an evidence-scoped controller exist. Native kernels, KV tensors and draft verification belong to llama.cpp. The full-distribution speculative reference is mathematically tested on finite models but is not the native serving path; real stochastic speculation remains unsupported or explicitly falls back.

The adaptive policy qualifies only exact public synthetic prompt hashes with three-session greedy-equivalence evidence. Unknown real-world prompts remain standard. No model/precision substitution is automatically qualified: Q4 fails the proposed PPL tolerance; Q8 lacks sufficient representative held-out task evidence. A 22-task smoke score does not establish broad instruction-following, reasoning or coding quality. The current 0.5B baseline itself fails half those strict smoke tasks.

Scheduling admits one active request with priority/aging and a bounded queue. It is non-preemptive, so a long active generation can delay short work. Continuous native batching and multi-active cancellation isolation are not implemented; this is a real remaining serving requirement. Lowest-compute preference is rejected because no validated compute-cost model exists. GPU, Apple Silicon and alternative backends remain untested/unimplemented.

Reported speed differences apply to warmed synthetic prefixes and delegate reuse to llama.cpp. Both arms exclude identical priming requests; there is no amortized total-workload benefit claim including priming, no custom kernel/paged-allocator claim, and no superiority claim over a tuned backend with prefix reuse already enabled. Shared-VM development activity and missing worker-swap histories in original experiments limit benchmark isolation. Energy, exact allocator peaks, fragmentation and true token-level intervals are unavailable.

Source/artifact locks and raw observations are preserved locally, with an archived executable frozen standard source snapshot. Model weights and native binaries are not packaged. Remote repository access/publication remains unresolved; no release or tag has been published. These limits must remain visible in G1–G10 rather than weakening acceptance to label the project 1.0.
