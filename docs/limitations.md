# Development-build limitations and release concerns

This is not Lattice 1.0. Real CPU generation, streaming, bounded priority admission, explicit model/precision switching, greedy native speculation, isolated prefix eligibility, benchmark/quality infrastructure and an evidence-scoped controller exist. Native kernels, KV tensors and draft verification belong to llama.cpp. The full-distribution speculative reference is mathematically tested on finite models but is not the native serving path; real stochastic speculation remains unsupported or explicitly falls back.

The adaptive policy qualifies only exact public synthetic prompt hashes with three-session greedy-equivalence evidence. Unknown real-world prompts remain standard. No model/precision substitution is automatically qualified: Q4 fails the proposed PPL tolerance; Q8 lacks sufficient representative held-out task evidence. A 22-task smoke score does not establish broad instruction-following, reasoning or coding quality. The current 0.5B baseline itself fails half those strict smoke tasks.

Serving now offers opt-in two-slot native continuous batching with verified per-request cancellation. A single long generation no longer blocks short work in the measured workload. The two-slot mode pins one model and standard execution; model swapping, cached/speculative execution and their serial quality policies remain in one-slot mode. Admission is non-preemptive once both slots are occupied, and two-slot performance is currently measured only for Qwen2.5 0.5B FP16 on this CPU. Lowest-compute preference is rejected because no validated compute-cost model exists. GPU, Apple Silicon and alternative backends remain untested/unimplemented.

Reported speed differences apply to warmed synthetic prefixes and delegate reuse to llama.cpp. Both arms exclude identical priming requests; there is no amortized total-workload benefit claim including priming, no custom kernel/paged-allocator claim, and no superiority claim over a tuned backend with prefix reuse already enabled. Shared-VM development activity and missing worker-swap histories in original experiments limit benchmark isolation. Energy, exact allocator peaks, fragmentation and true token-level intervals are unavailable.

Source/artifact locks and raw observations are preserved locally, with an archived executable frozen standard source snapshot. Model weights and native binaries are not packaged. Remote repository access/publication remains unresolved; no release or tag has been published. These limits must remain visible in G1–G10 rather than weakening acceptance to label the project 1.0.

Expanded [dataset intake](datasets.md) adds a 193,630-record curated catalog and [frozen quality observations](dataset_results.md), while preserving earlier smoke/performance studies. Volume is dominated by SQuAD, public benchmarks may be in model pretraining, authored templates are shared across splits, canonical rubrics can be stricter than semantic compliance and fixed output caps limit math performance. Eleven impossible inventory setups were quarantined after canonical-answer checks had passed, demonstrating why numeric/reference checks alone do not establish semantic dataset validity. Code execution and official IFEval scoring remain deferred; larger data volume does not qualify routing or precision substitution.

Experimental cost/coalescing admission supports explicit 3/4/8 slots as well, without changing defaults. Its first three-session burst confirmation failed exact-output preservation despite favorable performance metrics; all arms scored zero strict copy-task correctness under raw completion framing. Interactive-only and altered-arrival diagnostics expose regressions. These policies are conventional admission heuristics, do not infer validated task complexity, and provide no general competitive superiority or production SLA. See [confirmation](burst_admission_confirmation.md) and [boundaries](admission_boundaries.md).
